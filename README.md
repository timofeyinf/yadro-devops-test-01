# Тестовое задание для Команды разработки внутренней инфраструктуры и платформ продуктов

Проект состоит из 3 частей:
1. Работа со скриптом
2. Работа с Docker
3. Автоматизация процесса с помощью Ansible

Каждый раздел находится в своей директории.

---

### Раздел 1: Работа со скриптом

В этом разделе был написан скрипт на Python, с использованием библиотеки requests.

Изначально планировалось использовать сервис `httpstat.us`, но он не отвечал и возвращал пустой ответ. Это также было проверено через браузер и curl, после чего было решено использовать альтернативный сервис — `httpbin.org`. Минус этого сайта заключается в том что `/status/{code}` возвращает пустое тело ответа.

Скрипт отправляет GET-запросы на сервер с пятью разными HTTP-статусами и обрабатывает ответы:

- для кодов 1xx–3xx выводится информация 
- для кодов 4xx–5xx генерируется ошибка
- отдельно обрабатываются сетевые ошибки (например, если сервер недоступен)

Далее было создано виртуальное окружение venv, протестирована работа скрипта, установлены зависимости и зафиксированы в requirements.txt с помощью pip freeze.

---

### Раздел 2: Работа с Docker

В этом разделе был создан Docker-образ для запуска Python-скрипта из первого задания. 

Сначала был скопирован скрипт и файл зависимостей в отдельную директорию.

В Dockerfile:

- установлены Python3 и pip
- скопированы requirements.txt и установлены зависимости
- скопирован Python-скрипт
- сделан автоматический запуск скрипта при старте контейнера

Последовательность шагов в Dockerfile выбиралась мною в соответствии с подходом оптимизации кэширования слоев, чтобы при повторной сборке образа тяжелые шаги не выполнялись повторно при изменении скрипта или зависимостей.

После сборки образа был запущен контейнер и проверено, что скрипт корректно выполняется внутри него, также проверен вывод через docker logs.

### Раздел 3: Автоматизация процесса с помощью Ansible

Написан Ansible playbook для автоматизации установки Docker и проверки работы приложения внутри контейнера. В качестве хостов использованы две виртуальные машины на базе Linux Ubuntu. 

Создана удобная структура (такой подход использовался в моих прошлых проектах):

```text
section3-ansible/
.
├── ansible.cfg
├── files
│   ├── Dockerfile
│   ├── http_client.py
│   └── requirements.txt
├── group_vars
│   └── vm.yml
├── inventory
│   └── hosts.txt
└── playbooks
    └── docker_http_client.yml
```

Playbook выполняет следующие действия:

- Подключается к хостам (двум ВМ), которые указаны в inventory в файле `hosts.txt`
- Устанавливает Docker и необходимые зависимости
- Запускает и включает Docker
- Добавляет пользователя в группу docker
- Проверяет корректность установки с помощью команды `docker --version`
- Копирует необходимые файлы проекта на хосты из директории files
- Собирает Docker-образ
- Запускает контейнер с Python-скриптом
- Получает и выводит логи контейнера с помощью Ansible (docker logs), в них отображаются HTTP-запросы и их результаты
- Проверяется корректность выполнения скрипта - выводится код завершения (exit code = 0 означает успешное выполнение)
